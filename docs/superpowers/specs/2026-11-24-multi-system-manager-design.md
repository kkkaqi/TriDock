# 多系统管理器设计

用户已确认：Windows 桌面统一管理 Android、iOS、OpenHarmony，安装包不附带系统镜像，用户下载后导入，应用拖入安装。

保留 IPA Runner 的已有 iOS 应用库。新增系统实例页、按实例隔离的应用记录，以及 Android SDK Emulator、ASoftware iOS、Oniro OpenHarmony 三个独立适配器。只引用外部运行目录，不复制镜像、不自动下载系统、不扫描或删除用户磁盘内容。

首批支持可明确校验的外部环境：Android SDK 已创建的 AVD；已部署的 ASoftware iOS 16 目录；Oniro x86_64 images 目录。下载帮助直接指向项目文档。原始 ISO/IPSW 和任意硬件开发板固件不视作可启动环境。

实例保存名称、平台、运行目录、设备目标、工具路径和适用的 CPU/内存参数。启动记录进程身份，停止只作用于本软件创建的进程树。实例删除仅删除管理记录，保留外部镜像、用户数据与日志。资源参数只用于明确支持的后端；iOS 使用运行环境自己的配置。

APK 通过指定 adb 目标安装，aapt2 读取包名后启动。HAP 读取模块信息，通过指定 hdc 目标安装并调用 aa 启动。IPA 复用已有解析和 ASoftware 队列；安装成功与失败使用运行环境真实回报，现代 iOS 应用启动入口暂为系统桌面。未完成系统引导时给出等待/失败信息。

应用包保留原路径并记录哈希，避免后台积累副本。导入与启动均验证平台、路径和目标。长操作在后端子进程进行，界面保留可读状态和日志入口。下载大镜像与真实虚拟机首次启动不自动执行。

验证分为 Python 行为测试、Electron 导航/表单/拖入测试、无系统镜像打包检查。真实系统启动与性能测试需要用户已准备的相应运行环境，未实测不能宣称通过。
